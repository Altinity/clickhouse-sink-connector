### ClickHouse Sink Connector Release v2.10.0 Notes

2.10.0 is a large reliability release. It stops several classes of silent data loss (DDL ordering, TRUNCATE timing, keyless tables, BIT/DOUBLE mapping, history-mode row drops, offset commits), adds dump/load/compare tooling, and hardens how the connector fails.

**Full Changelog**: https://github.com/Altinity/clickhouse-sink-connector/compare/2.9.1...2.10.0

---

#### What's New

* **`ch_sink_tools` Python toolkit** — dump, load, and compare MySQL/PostgreSQL against ClickHouse (`ch-checksum`, `ch-pg-dump`, `ch-mysql-dump`, and related commands). Passwords are masked in logs, `eval()` is removed from checksum formatting, and table locks are held only for the duration of each table checksum. ([#1272](https://github.com/Altinity/clickhouse-sink-connector/pull/1272), [#1356](https://github.com/Altinity/clickhouse-sink-connector/pull/1356), [#1357](https://github.com/Altinity/clickhouse-sink-connector/pull/1357), [#1318](https://github.com/Altinity/clickhouse-sink-connector/pull/1318))
* **Ansible + systemd deployment** for the lightweight connector (no Docker, Kubernetes, or Kafka required). See `deploy/ansible-systemd/`. ([#1338](https://github.com/Altinity/clickhouse-sink-connector/pull/1338))
* **Optional REST API Basic Auth** — set `rest.api.auth.enabled=true` with `rest.api.auth.username` / `rest.api.auth.password`. Auth remains off unless enabled. ([#1300](https://github.com/Altinity/clickhouse-sink-connector/pull/1300))
* **Non-locking snapshot options** — additional snapshot locking modes so initial snapshots can avoid holding source table locks. ([#1380](https://github.com/Altinity/clickhouse-sink-connector/pull/1380))
* **`db_time` column** on binlog-history tables (`DateTime MATERIALIZED now()`) for when the row was written to ClickHouse. ([#1283](https://github.com/Altinity/clickhouse-sink-connector/pull/1283))
* **ClickHouse JDBC driver 2.10.** ([#1278](https://github.com/Altinity/clickhouse-sink-connector/pull/1278))
* **Fatal ClickHouse error classification** — authentication, schema mismatch, type mismatch, too-many-parts, and similar deterministic failures stop the connector instead of retrying the same batch forever and blocking every table. Transient errors still retry. ([#1315](https://github.com/Altinity/clickhouse-sink-connector/pull/1315))
* **Helm chart** — `connector.snapshotMode` (default `schema_only`) and `connector.disableDropTruncate` (default `true`) are now configurable. ([#1359](https://github.com/Altinity/clickhouse-sink-connector/pull/1359))
* **Updated `show_replica_status` view.** ([#1328](https://github.com/Altinity/clickhouse-sink-connector/pull/1328))
* **Sysbench automated tests** and pytest checksum integration tests. ([#1354](https://github.com/Altinity/clickhouse-sink-connector/pull/1354), [#1351](https://github.com/Altinity/clickhouse-sink-connector/pull/1351))

#### Breaking Changes

Upgrade notes — read these before rolling 2.10.0 into production.

1. **Keyless MySQL tables can refuse startup** ([#1401](https://github.com/Altinity/clickhouse-sink-connector/pull/1401), [#1405](https://github.com/Altinity/clickhouse-sink-connector/pull/1405), [#1406](https://github.com/Altinity/clickhouse-sink-connector/pull/1406), [#1407](https://github.com/Altinity/clickhouse-sink-connector/pull/1407))

   A table with no `PRIMARY KEY` and no non-null `UNIQUE` key has no row identity in the binlog. The connector now:

   * Refuses to start if it finds such tables on the source (and prints the exact `ALTER TABLE ... ADD COLUMN my_row_id ...` fix).
   * Refuses keyless tables on MySQL &lt; 8.0.30 and MariaDB (Generated Invisible Primary Key is not available).
   * Does **not** enable GIPK on the source. The connector is read-only against MySQL.
   * Does **not** block startup for tables that are already excluded from replication.

   **What to do:** add a GIPK (or a real primary key) on the source, or set `keyless.table.check.skip=true` if you accept silent row collapse.

2. **Helm defaults no longer snapshot existing data or apply DROP/TRUNCATE** ([#1359](https://github.com/Altinity/clickhouse-sink-connector/pull/1359))

   | Setting | Previous chart behavior | 2.10.0 default |
   |---|---|---|
   | `connector.snapshotMode` | pinned to `initial` | `schema_only` |
   | `connector.disableDropTruncate` | not configurable | `true` |

   Fresh Helm deploys will not load existing source rows and will ignore `DROP` / `TRUNCATE`. Override in `values.yaml` if you need the old behavior:

   ```yaml
   connector:
     snapshotMode: "initial"
     disableDropTruncate: "false"
   ```

3. **Fatal ClickHouse errors stop the connector** ([#1315](https://github.com/Altinity/clickhouse-sink-connector/pull/1315))

   Auth failures, unknown table/database/column, type mismatch, `TOO_MANY_PARTS`, and similar errors used to retry forever and stall the whole pipeline. They now fail the task. Configure alerting/restarts around a stopped connector; do not expect an infinite retry loop to hide a bad schema or credential.

4. **Sample Docker config no longer enables replicated table engines** ([#1301](https://github.com/Altinity/clickhouse-sink-connector/pull/1301))

   `auto.create.tables.replicated` is commented out / false in the sample `config.yml`. New tables are created as `ReplacingMergeTree`, not `ReplicatedReplacingMergeTree`. Set `auto.create.tables.replicated: "true"` if you need replicated engines.

5. **Auto-created column types changed for new tables**

   Existing ClickHouse tables are not rewritten. Newly auto-created tables use:

   * `BIT(n)` for `n > 1` → binary string, not `Bool` ([#1386](https://github.com/Altinity/clickhouse-sink-connector/pull/1386), [#1387](https://github.com/Altinity/clickhouse-sink-connector/pull/1387), [#1390](https://github.com/Altinity/clickhouse-sink-connector/pull/1390))
   * `DOUBLE` / `DOUBLE PRECISION` / `FLOAT8` → `Float64` (was `Float32`) ([#1386](https://github.com/Altinity/clickhouse-sink-connector/pull/1386))
   * `REAL` → does not claim `Float64` precision it never receives ([#1397](https://github.com/Altinity/clickhouse-sink-connector/pull/1397))
   * Unsigned integer mapping workaround for a Debezium bug ([#1306](https://github.com/Altinity/clickhouse-sink-connector/pull/1306))

   Recreate (or `MODIFY COLUMN`) any table that was auto-created under the old mapping if you need the corrected types.

#### Bug Fixes

**CDC / DDL ordering**

* Apply DDL at its position in the stream so pre-ALTER rows are not written after the schema change. ([#1385](https://github.com/Altinity/clickhouse-sink-connector/pull/1385))
* Execute `TRUNCATE` at its binlog position, not after the batch inserts. ([#1382](https://github.com/Altinity/clickhouse-sink-connector/pull/1382))
* `ALGORITHM` / `LOCK` clauses no longer discard later operations in the same `ALTER`. ([#1381](https://github.com/Altinity/clickhouse-sink-connector/pull/1381))
* Fix double database prefix on `TRUNCATE`, `DROP`, and `RENAME`. ([#1316](https://github.com/Altinity/clickhouse-sink-connector/pull/1316))
* Invalidate the cached writer for the source table of a `RENAME`. ([#1384](https://github.com/Altinity/clickhouse-sink-connector/pull/1384))
* Wait for `ALTER TABLE` visibility before cache invalidation. ([#1321](https://github.com/Altinity/clickhouse-sink-connector/pull/1321))
* Fix cache invalidation logic (with integration test). ([#1333](https://github.com/Altinity/clickhouse-sink-connector/pull/1333))
* Generated `ADD` / `DROP` / `RENAME` DDL is replay-safe after a restart (`IF EXISTS` / `IF NOT EXISTS`). Replay safety uses version **ordering**, not equality. ([#1402](https://github.com/Altinity/clickhouse-sink-connector/pull/1402), [#1403](https://github.com/Altinity/clickhouse-sink-connector/pull/1403), [#1404](https://github.com/Altinity/clickhouse-sink-connector/pull/1404))
* DDL waiter no longer parses `IF NOT EXISTS` as the column name. ([#1408](https://github.com/Altinity/clickhouse-sink-connector/pull/1408))
* Default `MODIFY` / `CHANGE COLUMN` to `Nullable` when ClickHouse schema metadata is unavailable. ([#1339](https://github.com/Altinity/clickhouse-sink-connector/pull/1339), [#1341](https://github.com/Altinity/clickhouse-sink-connector/pull/1341))
* A column rename no longer NULLs rows still in flight. ([#1395](https://github.com/Altinity/clickhouse-sink-connector/pull/1395))
* Pre-ALTER rows NULL-fill newly added columns instead of failing. ([#1389](https://github.com/Altinity/clickhouse-sink-connector/pull/1389))

**Data integrity**

* Delete operations are persisted. ([#1281](https://github.com/Altinity/clickhouse-sink-connector/pull/1281))
* `_version` is anchored to the source commit timestamp so a re-delivered `DELETE` cannot out-rank a later re-`INSERT`. Formula stays the 2.8.0 `ts_ms * 1_000_000 + counter` domain (upgrade- and rollback-safe). ([#1378](https://github.com/Altinity/clickhouse-sink-connector/pull/1378))
* History mode no longer drops all but the first row of a multi-row binlog event. ([#1391](https://github.com/Altinity/clickhouse-sink-connector/pull/1391))
* Kafka Connect `preCommit` only advances offsets after a durable ClickHouse insert. ([#1345](https://github.com/Altinity/clickhouse-sink-connector/pull/1345))
* Retry offset flushing on process error. ([#1335](https://github.com/Altinity/clickhouse-sink-connector/pull/1335))
* A nullable `UNIQUE` key no longer stalls the entire stream. ([#1396](https://github.com/Altinity/clickhouse-sink-connector/pull/1396))
* Keyless / no-PK tables no longer collapse to a single row (see Breaking Changes for the GIPK requirement). ([#1389](https://github.com/Altinity/clickhouse-sink-connector/pull/1389), [#1394](https://github.com/Altinity/clickhouse-sink-connector/pull/1394), [#1401](https://github.com/Altinity/clickhouse-sink-connector/pull/1401))

**Types and schema**

* `BIT(n)` poison-batch stall, byte-reversal, and binary safety. ([#1386](https://github.com/Altinity/clickhouse-sink-connector/pull/1386), [#1387](https://github.com/Altinity/clickhouse-sink-connector/pull/1387), [#1390](https://github.com/Altinity/clickhouse-sink-connector/pull/1390))
* `DOUBLE` precision loss (`Float32` → `Float64`). ([#1386](https://github.com/Altinity/clickhouse-sink-connector/pull/1386))
* TTL hardcoded value and `Nullable(DateTime64)` precision. ([#1342](https://github.com/Altinity/clickhouse-sink-connector/pull/1342))
* Unsigned mapping workaround for a Debezium bug. ([#1306](https://github.com/Altinity/clickhouse-sink-connector/pull/1306))

**Startup and operations**

* NullPointerException on cold start when ClickHouse is unreachable. ([#1348](https://github.com/Altinity/clickhouse-sink-connector/pull/1348), [#1349](https://github.com/Altinity/clickhouse-sink-connector/pull/1349))
* Guard against null JDBC params/settings in `BaseDbWriter.createConnection`. ([#1340](https://github.com/Altinity/clickhouse-sink-connector/pull/1340))
* Check whether a view exists before creating it. ([#1344](https://github.com/Altinity/clickhouse-sink-connector/pull/1344))
* Docker Compose `depends_on` healthcheck so the connector does not start before ClickHouse is ready. ([#1332](https://github.com/Altinity/clickhouse-sink-connector/pull/1332))
* SourceRecordParserService null-schema and error-handling hardening. ([#1360](https://github.com/Altinity/clickhouse-sink-connector/pull/1360))
