### ClickHouse Sink Connector Release v2.11.0 Notes

2.11.0 is the spec-driven release. Every replication invariant is now declared in `specs/` and machine-checked in Lean 4 (`formal_specs/`), and the runtime was hardened to match: offsets commit in FIFO order, `_version` is monotonic across restarts, the data path is bounded in bytes, and PostgreSQL is a first-class source.

---

#### Highlights

* **PostgreSQL CDC support** — PostgreSQL is now a first-class source alongside MySQL: WAL streaming ported onto the 2.11.0 line, a `ch-pg-dump` snapshot tool anchored to the replication slot, honest PG verification verdicts, and a Postgres type mapper. ([#1435](https://github.com/Altinity/clickhouse-sink-connector/pull/1435), [#1540](https://github.com/Altinity/clickhouse-sink-connector/pull/1540), [#1541](https://github.com/Altinity/clickhouse-sink-connector/pull/1541), [#1530](https://github.com/Altinity/clickhouse-sink-connector/pull/1530))
* **Spec-driven development with Lean 4 formal verification** — the repository now declares every behavioural invariant in `specs/` and proves offset ordering, version monotonicity and convergence in `formal_specs/lean`, validated in CI on every pull request. ([#1460](https://github.com/Altinity/clickhouse-sink-connector/pull/1460), [#1463](https://github.com/Altinity/clickhouse-sink-connector/pull/1463), [#1473](https://github.com/Altinity/clickhouse-sink-connector/pull/1473), [#1466](https://github.com/Altinity/clickhouse-sink-connector/pull/1466))
* **Primary-key rebuild at the DDL barrier** — when the source changes a primary key, the connector rebuilds the replica (swap + backfill, `ON CLUSTER` in replicated mode, cancellable safely) instead of silently drifting. ([#1483](https://github.com/Altinity/clickhouse-sink-connector/pull/1483))
* **SCD2 history and replication-log-only modes** — per-table slowly-changing-dimension history and a replication-log-only mode, specified and proven with a formal model. ([#1507](https://github.com/Altinity/clickhouse-sink-connector/pull/1507), [#1511](https://github.com/Altinity/clickhouse-sink-connector/pull/1511), [#1512](https://github.com/Altinity/clickhouse-sink-connector/pull/1512))
* **Key-aware row routing** — one hot table can spread across writer threads while preserving per-key ordering. ([#1523](https://github.com/Altinity/clickhouse-sink-connector/pull/1523), [#1465](https://github.com/Altinity/clickhouse-sink-connector/pull/1465))
* **Writer throughput** — INSERT templates, column types and formatters derived once per batch instead of once per row (1.9x per-batch throughput, byte-identical output); queued batches behind the polled one coalesce into a single write bounded by `buffer.max.records` / `buffer.max.bytes`; `coalesce.max.wait.ms` bounds ClickHouse part creation per wait instead of per poll. ([#1524](https://github.com/Altinity/clickhouse-sink-connector/pull/1524), [#1525](https://github.com/Altinity/clickhouse-sink-connector/pull/1525), [#1526](https://github.com/Altinity/clickhouse-sink-connector/pull/1526))
* **Compressed binlog transactions** — MySQL compressed transaction payloads replicate correctly and stream in constant memory regardless of uncompressed size; dead binlog connections restart instead of stalling. ([#1531](https://github.com/Altinity/clickhouse-sink-connector/pull/1531), [#1533](https://github.com/Altinity/clickhouse-sink-connector/pull/1533), [#1534](https://github.com/Altinity/clickhouse-sink-connector/pull/1534))
* **`ch-mysql-resync` repair tool** — re-synchronise replica tables after a source change that bypassed the binlog (`sql_log_bin=0` patch): dump, count-reconciled scratch load, atomic `REPLACE PARTITION`, connector offset rewind. ([#1521](https://github.com/Altinity/clickhouse-sink-connector/pull/1521), [#1542](https://github.com/Altinity/clickhouse-sink-connector/pull/1542))
* **Consistent checksums** — `db_compare` can lock and wait for the connector, or take per-slice consistent snapshots, and a checksum driver never reports an unverified table as equal. ([#1548](https://github.com/Altinity/clickhouse-sink-connector/pull/1548), [#1549](https://github.com/Altinity/clickhouse-sink-connector/pull/1549), [#1550](https://github.com/Altinity/clickhouse-sink-connector/pull/1550), [#1551](https://github.com/Altinity/clickhouse-sink-connector/pull/1551), [#1539](https://github.com/Altinity/clickhouse-sink-connector/pull/1539))
* **Bounded memory and backpressure** — a hard cap on rows handed off but not yet acknowledged (the reader pauses instead of filling the heap), the data path bounded in bytes not only rows, large INSERT chunks spilled to disk, and the process-lifetime leaks closed. ([#1503](https://github.com/Altinity/clickhouse-sink-connector/pull/1503), [#1505](https://github.com/Altinity/clickhouse-sink-connector/pull/1505), [#1536](https://github.com/Altinity/clickhouse-sink-connector/pull/1536), [#1506](https://github.com/Altinity/clickhouse-sink-connector/pull/1506))
* **Offset-commit correctness** — offsets commit in handoff-sequence FIFO order, a written batch is never re-executed, worker death stops the pipeline loudly, and the `OffsetStorageWriter` flush-semaphore leak is closed. ([#1471](https://github.com/Altinity/clickhouse-sink-connector/pull/1471), [#1447](https://github.com/Altinity/clickhouse-sink-connector/pull/1447), [#1464](https://github.com/Altinity/clickhouse-sink-connector/pull/1464), [#1566](https://github.com/Altinity/clickhouse-sink-connector/pull/1566))
* **Monotonic `_version` across restarts** — a durable version floor seeded at start, GTID path floored by commit order; a commit that reaches the binlog late can no longer lose to an earlier write of its key. ([#1478](https://github.com/Altinity/clickhouse-sink-connector/pull/1478), [#1485](https://github.com/Altinity/clickhouse-sink-connector/pull/1485), [#1452](https://github.com/Altinity/clickhouse-sink-connector/pull/1452))
* **DDL translation overhaul** — MySQL ALTER/CREATE translated to what ClickHouse actually accepts, generated columns become `DEFAULT` (never `MATERIALIZED`), every handoff path drains before a DDL, and an unapplied DDL halts the pipeline loudly instead of being swallowed. ([#1472](https://github.com/Altinity/clickhouse-sink-connector/pull/1472), [#1479](https://github.com/Altinity/clickhouse-sink-connector/pull/1479), [#1442](https://github.com/Altinity/clickhouse-sink-connector/pull/1442), [#1445](https://github.com/Altinity/clickhouse-sink-connector/pull/1445), [#1461](https://github.com/Altinity/clickhouse-sink-connector/pull/1461))
* **Initial snapshot reliably completes** — heartbeats are enabled and the post-snapshot heartbeat offset is committed, so `snapshot_completed` is persisted and the engine transitions to streaming. ([#1438](https://github.com/Altinity/clickhouse-sink-connector/pull/1438), [#1428](https://github.com/Altinity/clickhouse-sink-connector/pull/1428), [#1467](https://github.com/Altinity/clickhouse-sink-connector/pull/1467))
* **Apache-2.0 license compliance** — no GPL/LGPL code in the connector JARs; `THIRD_PARTY_NOTICES.md` and full license texts ship with the distribution. ([#1560](https://github.com/Altinity/clickhouse-sink-connector/pull/1560), [#1561](https://github.com/Altinity/clickhouse-sink-connector/pull/1561), [#1564](https://github.com/Altinity/clickhouse-sink-connector/pull/1564))

#### Behaviour changes to note on upgrade

* **`clamp.out.of.range` defaults to `true`** — an out-of-range source value saturates to the column's bound and is reported, instead of stopping replication. ([#1490](https://github.com/Altinity/clickhouse-sink-connector/pull/1490))
* **`connect.keep.alive` defaults to `false`** — a lost binlog connection restarts the engine at a transaction boundary instead of resuming mid-statement and silently dropping rows. ([#1500](https://github.com/Altinity/clickhouse-sink-connector/pull/1500))
* **FATAL failures are terminal at once, never retried**; the engine retry budget refills on progress, not on a bare start. ([#1487](https://github.com/Altinity/clickhouse-sink-connector/pull/1487), [#1489](https://github.com/Altinity/clickhouse-sink-connector/pull/1489))
* **`TOO_MANY_PARTS` (252) is retriable backpressure, not fatal.** ([#1462](https://github.com/Altinity/clickhouse-sink-connector/pull/1462))
* **Per-batch progress lines moved to DEBUG**; the resume replay is summarized instead of dumping every skipped row image; hard-cap and high-water-mark warnings are paced. ([#1488](https://github.com/Altinity/clickhouse-sink-connector/pull/1488), [#1509](https://github.com/Altinity/clickhouse-sink-connector/pull/1509), [#1504](https://github.com/Altinity/clickhouse-sink-connector/pull/1504))
* **Debezium JDBC storage keys renamed** — shipped configs use the current `offset.storage.jdbc.offset.table.*` spellings; the pre-2.7.1 names still work but log a deprecation error on every start. ([#1518](https://github.com/Altinity/clickhouse-sink-connector/pull/1518))
